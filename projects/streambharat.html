01 / STREAMBHARAT · 2026 · SIX-MEMBER TEAM PROJECT

An OTT data platform built around batch analytics and streaming signals.

StreamBharat is a course-scoped data engineering platform for a fictional Indian OTT service. It combines multi-domain ingestion, a Bronze/Silver/Gold lakehouse workflow, business analytics, and two simulator-driven Structured Streaming jobs.

The data problem

OTT products generate data across playback, subscriptions, catalogue, search, advertising, and CDN operations. These sources differ in structure and business meaning, so analytics depends on cleaning events, reconciling records, modelling dimensions, and producing consistent downstream datasets.

Project architecture

The batch path moves source data through raw/bronze, silver, and gold layers for reporting and analytical use cases. Separate streaming entry points consume simulator-emitted JSON files for live trending and ad frequency/pacing demonstrations.

Testing and engineering checks

The repository includes deterministic business-rule tests, Python compilation checks in GitHub Actions, a finite batch orchestrator, and a dry-run mode for inspecting stage order. These checks are useful, but they do not substitute for executing every Spark job against the full dataset.

Scope and validation status

This is a learning/workbook project using synthetic sample data, not a deployed production OTT platform. The repository documents all 20 question modules and the two streaming entry points. Full Spark/Delta integration, complete dataset reconciliation, streaming restart and late-event tests, and measured model-performance metrics are explicitly listed as outstanding validation work. The project does not claim Kafka, Airflow, PostgreSQL, or a deployed BI serving layer as part of the core workbook implementation.

For the latest state, test commands, dataset conventions, architecture and workstream notes, consult the source repository README and its GitHub Actions.
